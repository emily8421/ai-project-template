# TEMPLATE-UPGRADE: 沙箱环境验证降级与 spawn 失败分流

> 来源：模板维护者（模板仓自产，2026-09-03）。
> 状态：已实施（PR #429 squash `8b1ee4a`，2026-09-03），本提案同日归档。
> Release impact：MINOR（已确认，随 v1.72.0 发版；三个文件均在下行同步清单）。

## 1. 动机

2026-09-02 模板仓一次 registry 登记被自检故障阻塞约 20 小时：`scripts/check-template.sh --summary` 死于子进程创建阶段（Win32「系统找不到指定的文件」），后续复核确认为沙箱化 CLI（Codex CLI 沙箱）限制进程创建所致——同一脚本、同一提交在非沙箱 shell 完整重跑与 CI 均通过，脚本本身无缺陷。维护者实际协作中 AI CLI 不固定（Claude Code / Codex 等混用），本缺口可在任何沙箱化执行环境复现。规则缺位点有二：

1. **环境能力预判缺位**：沙箱 / 受限环境内执行了会大量创建子进程的全量自检（数千次 spawn），无人拦。
2. **失败定性缺位**：spawn 类进程错误无分流口径，被误判为「模板自检故障」，阻塞了本可凭 CI 先行收尾的登记工作。

## 1.1 与既有规则的关系（去重）

- #423 / PR #424（v1.71.1「跨 Shell 路径预检与失败域隔离」）管路径与查询层面的跨 Shell 无副作用预检；本提案管执行环境能力（进程创建）限制下的验证降级与失败定性——同族不同点，互补不重复。
- 既有「失败即停」（`ai/rules-core.md` §2 / `ai/session-rules.md` §3.3 第 4 条）只规定「停」；本提案补「停之后如何定性与继续」，且不放宽其停止语义。
- `ai/session-rules.md` §3.3 的改动仅一句分流口径加指针，不重复正文（沿 #424「不改 session-rules 避免重复」的收敛先例，但此处为补分流语义而非重复停止语义）。

```markdown
- **沙箱 / 受限环境验证降级与 spawn 失败分流**：运行会大量创建子进程的全量自检 / 全量验证前，先自问当前环境是否沙箱或权限受限（如 Codex CLI 沙箱）；受限则不在本地跑全量验证，改用非沙箱 shell 直跑或以 CI 为准，并在收尾说明验证环境局限。验证命令以进程创建类系统错误中断（如 spawn 失败、Win32「系统找不到指定的文件」，且无断言失败输出）时，先判定为环境故障——换非沙箱环境复核一次再定性，不得记为脚本或产物缺陷，也不得以此阻塞登记 / 收尾类工作（验证结论仍须以 CI 或非沙箱复核为准）。
```

## 3. 边界与风险

- **不改脚本**：`check-template.sh` 不加沙箱启动探测——故障为大量 spawn 成功后的累积型失败，启动时 smoke 无法可靠预测；机械预检不可靠，故走规则 + 执行节点（rules-core 为所有非快速续接任务的必读门禁）。
- **不引入关键词硬拦**：采用问句式自检（「当前环境是否沙箱受限？」）与错误特征描述，避免误伤合法技术表达（沿用「行为约束接入执行节点」既定口径）。
- **「不阻塞登记 / 收尾」的边界**：仅指登记 / 文档收尾不必等待环境故障解决；任何「已验证」结论仍须以 CI 或非沙箱复核为准，不得把环境故障写成验证通过。
- **不放宽失败即停**：构建、测试、写入、迁移、网络、CI、远端与断言类失败仍一律停止；分流仅适用于「无断言失败输出的进程创建类错误」。
- 不改同步清单、版本号（发版随实施 PR 单独决定）。
