> 状态：已落地（PR #443，squash `6372549`，v1.73.0）；issue #441 关闭；2026-09-09 归档

> Release impact：minor（路由表新增章节级标注语义与同会话复用注记，属推荐工作流变化；无标注场景行为零变化、不要求派生项目迁移）
> Release strategy：同主题聚合（Batch B 三提案 #441 / #440 / #439 各自 PR，统一 v1.73.0 发版，先例 v1.68.0）

## 1. 动机（去项目化）

模板的规则路由体系已解决「读哪些文件」（`ai/index.md` 路由表）与「不预读全模板」（`ai/rules-core.md` §4），但路由条目的粒度是**整文件**。来源项目跨三个 token hotspot rollup 阶段累计 11+ 实例（其中 3 份已提炼入库）表明：相当一部分任务类型对规则的引用面集中于少数章节，整文件加载构成该类任务的主要上下文成本：

1. **提案起草 / 回流评估类**：按「文档任务」路由整读 4 份大规则，实际高相关仅 2-4 个章节——通用规则 §9 / §10、文档生命周期 §2 与 §7.1 状态词典、命令文件全文。
2. **分析 / 评估 / 回测类**：规范基线全文读入，实际仅引用 2 个章节（如 doc-standards 的 03 §3 §4、09 §3 §4）。
3. **同会话续接升级类**：快速续接 → 分析任务升级后，同一规则文件同会话二次整读——`ai/session-rules.md` §3.2 复用边界实际已允许复用，但路由入口未接入该条款。
4. **工具脚本类**：一次性 `.tmp` 诊断 / 验证脚本走了完整编码任务路由。

体系内已存在两种粒度形态且不一致：路由表是整文件粒度；命令文件已示范章节级窄必读集（`ai/commands/submit-proposal.md` 必读仅 3 项且引用到 `ai/global-rules.md` §9，2026-09-09 triage 核实属实）。模板已验证窄必读集可用，只是没有反哺到路由表。

**缺口（本提案补）**：路由表从「整文件必读」升级为「支持章节级标注」，并把同会话复用条款接到路由入口；不改路由门禁本身。

## 1.1 与既有规则的关系（去重）

- **`ai/index.md` 任务路由表**：**直接增强对象**——表结构与任务包划分原样保留，仅在必读规则包的文件引用上增加可选章节级标注。
- **`ai/rules-core.md` §3「先读该文件目录 / 相关章节」**：**升格既有启发式**——该句已隐含按章节读合规，本提案把它升格为路由表显式标注的常规选项，互为表里。
- **`ai/rules-core.md` §4（按层读取、不预读全模板）**：**同向、粒度递进**——§4 管不跨层预读（文件级），本提案管层内按章节收窄（章节级）。
- **`ai/session-rules.md` §3.2（同会话规则复用边界）**：**接入口**——本体不动，路由表脚注加指针，使快速续接升级场景不再二次整读。
- **`ai/session-rules.md` §3.1（快速续接最小读取）**：**先例佐证**——按场景定义最小读取已在快速续接模式运行，本提案推广到分析 / 提案类任务。
- **完整规则回退包**：**不动、兜底保留**——任务类型不明确 / 规则覆盖不足 / 不确定时仍读完整回退包；本提案只作用于能明确判断任务类型且该任务包存在标注的场景。
- **「不得为了省上下文跳过可能相关的硬规则」（rules-core §2/§3）**：**安全线，不削弱**——标注只收窄已证明引用面集中的任务类型；无标注任务默认整文件，行为不变。
- **#423（跨 Shell 路径预检，已落地）**：**对象不同**——#423 管 shell 命令预检，本提案管规则读取粒度。

**本提案不重复它们**：补的是「路由表条目粒度只有整文件、窄必读集无路由级入口」这块空白；差异化：在路由表内以标注形式落地，零脚本、零 CI 断言。

## 2. 拟改

### 2.1 落地位置

- **`ai/index.md` 路由表**：「文档 / 需求 / 设计 / 计划」行的 `ai/global-rules.md`、`ai/document-lifecycle-rules.md`、`ai/doc-standards/` 引用加首批章节级标注（均来自实证）；表下新增脚注一条，定义标注语义 + 同会话复用注记。
- **`ai/rules-core.md` §3**：「先读该文件目录 / 相关章节」句后加指针——路由表已标注章节的场景按标注读取即为合规。
- **不新增脚本 / CI 断言**：引用面是否集中是语义判断，无法机械化。

### 2.2 机制（三条）

1. **章节级标注语义**：条目内规则文件引用可选标注「（<场景>可只读 §x / §y）」。未标注 = 整文件（现状默认，行为不变）；标注场景下按所列章节读取即为合规；任务需要标注外内容或场景不符时按现状读全文——保守方向兜底。
2. **首批标注**（供维护者采纳或调整，均来自 §1 实证，2026-09-09 triage 逐条核实章节编号属实）：global-rules §9 / §10（模板优化反馈 / 文档语言与表述规范）、document-lifecycle §2 / §7.1（PLM 阶段链路 / 横切状态词典）、doc-standards 03 §3 §4（ID 与追溯 / Phase 规则）、09 §3 §4（TC 状态枚举 / 用例详情最低字段）。
3. **稳定锚点前提**：章节标注依赖既有章节编号规范（global-rules §5「文档编号规范」）——规则文件章节改编号须全量迁移引用，路由表标注随之更新，不新增独立维护机制。

### 2.3 力度

**建议 + 默认**：标注是否存在由模板维护者按实证逐步添加；派生项目可按标注执行，也可保守整读（不算违规）；无标注场景行为与现状完全一致；零 CI 断言。
