# TEMPLATE-UPGRADE：文档语言规范新增「公文腔词语」约束

## 1. 动机

派生项目实际使用中收到用户反馈：工程文档与 AI 生成内容中出现「口径」等公文腔 / 汇报腔词语，用户无法直解、需追问确认。此类词与 §10.6 已覆盖的抽象名词（赋能、沉淀、闭环等）性质不同：抽象名词条款的缓解手段是「说明具体对象 / 动作 / 边界」，而公文腔词存在更简单的解法——**任何时候都有平实、具体、可核对的同义替换**，替换后不损失信息。现有 §10 各条没有覆盖这一类别，AI 生成文档时无明确依据排除此类用词。

## 2. 拟改

在 `ai/global-rules.md` §10 增补一条（建议作为 §10.6 的扩展款或独立条目，编号由维护者定）：

> **避免公文腔 / 汇报腔词语**：不使用「口径」「抓手」「拉通」「颗粒度」「打法」等机构内部惯用缩略语，改用平实、具体、可核对的表述；按语境替换（如「口径」→「表述版本 / 数据基准 / 统计范围 / 以…为准 / 自报数据」）。已成行业通用术语的词不受限（承 §10.6 既有例外）；引用原始材料原文保持原样（承本节前言）。存量文档逐步修订，不做无目的批量改写（承 §10.7）。

## 3. 版本影响

建议 **MINOR**（新增文档生成行为约束，不改结构、不同步清单、不新增 CI / 自检断言、默认流程不变）。请维护者复核定级。

### 验证方式

语义类规则，不引入 check-template 断言（遵循「无自检门禁、避免过度治理」口径）。验证方式：派生项目以抽查方式核对新生成 / 新修改的文档与回复不再出现公文腔用词；模板侧由维护者在提案合并说明中记录定级与采纳范围，不新增脚本或 CI 门禁。

## 4. 影响面

- 行为面：AI 生成 / 修改所有项目事实文档、报告、回复时的用词选择；无流程、脚本、清单改动。
- 存量面：模板规则文件与历史记录中已存在的此类用词，按 §10.7 渐进适用原则**不要求批量清理**；仅新增与实际修改的内容受约束。`ai/doc-standards/` 与 `template-docs/docs-scaffold/` 撰写提要中的个别用词（如「验收口径」）可在文档被实际填写时顺带改写，不单独立项。

## 5. 与既有规则的关系（去重）

- §10.6 第三款已覆盖抽象名词（赋能、沉淀、闭环、全链路等）的「必须说明对象 / 动作 / 边界」要求——本提案**不重复**该机制，只新增「公文腔词语」这一类别及其「直接替换」缓解方式。
- §10.5（规范性用词）管约束等级词，§10.2（平实简洁）是原则性要求——本提案把「公文腔」从原则中具体化为可执行的禁用 + 替换清单示例，属于对既有原则的操作化，不冲突。
- 未检索到既有提案覆盖此项。
