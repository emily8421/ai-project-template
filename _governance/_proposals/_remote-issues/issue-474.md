# TEMPLATE-UPGRADE：web-fullstack-profile §10 应配套「组件库 vs 自绘」默认决策判据（三层承载结构）

> Release impact：提案文件本身 none；落地建议 PATCH（advisory 治理提醒增补，无默认行为变化）（AI 建议，待维护者确认）
> Release strategy：单独发布（advisory 条目，可同主题聚合）

## 1. 动机

§10（v1.74.0 新增「UI 组件库与样式承载声明」）要求选型结论「须声明」——管的是**把结论写下来**，没有回答**怎么得出结论**。对 AI 主导开发的派生项目，这一步恰是高风险空白：无默认判据时，AI 的承载方式选择不可控——要么沿既有代码惯性继续手写（行为层缺陷在下面实证），要么摆向另一极端引入整包组件库（与 token 单源双写冲突）。且选型结论一经「声明」即固化，首次选错会按声明的边界持续错下去。

派生项目实证（同一项目内完整证据链，均已发生事实）：

1. **手写行为层缺陷家族**：手写下拉菜单的「外点 / Esc 关闭」首次实现即漏边界（真实缺陷，修复后抽复用范式才收敛）；其前身浏览器原生确认行为存在十处一次性迁移债（实现缺位累积的集中偿还）；模态类焦点陷阱从未实现、无障碍契约从未系统验证——行为层实际状态是「已知出过缺陷 + 未知风险未盘点」，而非「已达标」。
2. **三层承载结构实战验证**：6 个「看不见的行为」组件（下拉菜单 / 气泡 / 模态 / 命令面板 / 非模态抽屉 ×2）迁移至无头行为库（headless，unstyled），行为层（外点 / Esc 关闭、焦点陷阱、键盘导航）全部交库，外观零变化；浏览器驱动冒烟逐项断言全过（含焦点陷阱 24 次 Shift+Tab 不出层）；全部质量门 PASS。
3. **豁免反例同样必要**：3 类件核实后留下不换——页内行内确认条（语义特殊，且有「确认动作前不发请求」的红线测试守护）、47 行外点关闭复用 hook（双树复用、已收敛范式）、面板拖拽 resizer（无标准库对应，自写合理）。实证「行为复杂度超出**合理**范围才引库」的「合理」一侧需要边界样本，否则判据会滑向一刀切。

## 1.1 与既有规则的关系（去重）

- 与 §10 既有声明机制（v1.74.0）：**同对象、补配套**——不动「声明项 / 兼容性核查 / 版本锁定 / 承载声明」任何既有条目，补的是声明之前的「怎么选」默认判据；判据产出即声明输入。
- 与 `ai/doc-standards/ui-prototype-strategy.md`（实现前原型门禁）：**层级不同**——该标准管原型可视化验证的时机与记录，本条管实现期组件承载方式决策，正交。
- 与 `template-docs/ui-knowledge/README.md` §4.3 REC-* 配方：**机制不同、互补**——REC 沉淀选型「结论」，判据约束选型「过程」；判据落地可指向 REC 作为结论沉淀出口（本提案不新增 REC 内容）。
- 与 §4 / §5.1 token 单源与样式纪律：**互补不冲突**——判据明确「视觉归 token、行为交库」；headless（unstyled）形态恰以零样式绑定回避双写，与 token 纪律同向。
- 与设计可驱动性六问（#407，v1.71.0）：**对象不同**——六问答「设计是否可驱动实现」，本条答「组件承载方式怎么选」。
- 与阶段准出档位判据（#439，v1.73.0）：**机制同构先例、对象不同**——「规范存在但缺配套判据」缺口此前在阶段准出域出现过并以同款方式补齐；本条是该缺口在组件选型域的第二实例，佐证模式而非重复内容。

## 2. 拟改

候选落点（维护者 triage 可调整；附 `-patch.md` 给基于当前模板版本的 old→new 建议）：

在 web-fullstack-profile §10 增补一条「承载方式默认判据」bullet（advisory，同节既有口径），要点：

- **三层结构口诀**：视觉自己写（token 归 token），行为优先买现成（headless 库），深水区用专项库；整包组件库与 token 单源双写冲突，默认排除、采用须论证。
- 普通静态组件与简单交互（按钮 / 卡片 / 列表 / tab / 徽标）→ **自绘**：AI 生成质量高、token 一致性可控。
- 浮层 / 下拉 / modal / 外点与 Esc 关闭 / 焦点陷阱 / 键盘导航等「看不见的行为」→ **默认引 headless 库**（Radix / React Aria 类），不手写；存量手写件按缺陷史与成本收益分批处置，换库时行为交库、外观零变化。
- 专项深水区（富文本编辑 / 虚拟化长列表 / 拖拽排序 / 日期时间选择）→ **专项库**。
- **判断口诀**：画得出来的自己写，看不见的行为买现成；豁免须给理由（语义特殊 / 已收敛范式 / 无标准库对应），豁免样本建议随声明一并登记。
- **无头库选型参考维度**：生态与 AI 语料规模（直接对应 AI 生成质量）、unstyled 与 token 体系零冲突、组件 vs hooks 形态替换成本、配套标准件同系可得（如命令面板标准件）。

一句话判据：**「结构性决策要声明」（§10 既有）之外，补「怎么决策」的默认判据——三层承载结构。**

## 5. 验证方式

- 实证层：派生项目已提供完整证据链（手写缺陷家族 → 三层判据草案 → 6 组件 headless 迁移实战：行为交库 + 外观零变化 + 冒烟断言全过 + 质量门全绿 → 豁免反例边界样本）；模板侧无需新建复现环境。

## 附录：行为库自动化验证注意（AI 协作语境，可选采纳）

无头行为库对「合成事件」与「原生事件」语义不同，AI 驱动浏览器冒烟验证时需注意（实证 3 坑，可作判据落地时的附注或并入壳 / E2E 手册）：

1. 触发件监听 `pointerdown` 序：脚本合成 `.click()` 可能无效，需浏览器驱动原生鼠标事件；
2. 外点关闭层（DismissableLayer 类机制）不响应合成 pointer 事件，外点断言须原生点击；
3. 层刚打开立即外点可能被「打开事件延续」抑制（实证静置约 300ms 后恢复正常），断言前需静置。
