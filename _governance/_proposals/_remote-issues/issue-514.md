# TEMPLATE-UPGRADE: 同步类任务路由补章节级标注（消解完整回退包固定启动成本）

> 来源：agent-system-template（emily8421/agent-system-template）派生项目回流
> 状态：**草案 · 待维护者确认**（2026-11-03 起草并提交母仓）
> 目标模板版本：ai-project-template v1.76.0+（本仓同步口径）
> Release impact：预估 MINOR（规则层读取语义放宽 + 路由标注新增；不改同步清单 / 脚本 / 自检断言，既有派生项目兼容，下行同步即生效）
> 仓库角色：B 组 · 待上行跨领域（回流母模板）

## 1. 动机

同步类任务（`sync-methodology` 命令链）按现行路由须全读**完整规则回退包**（`ai/rules-core.md` §3：「模板维护、规则变更、同步清单和自检脚本变更必须读取完整规则回退包」）。两轮实盘同步的 token hotspot 实测：

- v1.75.0 同步轮（2026-09-10）：完整回退包 + sync-methodology 命令链约 5 个大文件全读，是同步任务的固定启动成本；grep 摘要使 26 文件同步零全文读取，但规则读取省不掉。
- v1.76.0 同步轮（2026-11-02）：路由全读约 5 万 token 级；其中 `document-lifecycle-rules.md` 的 §5.2 UI 管线等大量章节**与同步动作零交集**，纯读取成本。

章节级标注机制自 v1.73.0 起已存在（`ai/index.md` 路由表脚注：「标注场景下按所列章节读取即为合规读取」），但同步类任务的路由行未挂标注，AI 只能保守全读——机制已有，覆盖面缺一块。

## 2. 拟改

三处，建议渐进式落地：

1. **`ai/index.md` 路由表**：同步场景行挂章节级标注。首批只标实证最明确的一项：
   - `ai/document-lifecycle-rules.md`（同步场景可只读 §2 E6 / §9 变更传播）
   - 其余回退包文件的适用章节由维护者按同样方法（对照实盘同步轮实际查阅内容）核对后逐步标注；未标注文件维持全读，不影响合规。
2. **`ai/rules-core.md` §3**：区分两类动作，避免语义冲突——
   - **执行同步轮**（按已发布版本做例行下行同步）：可按标注章节读取；
   - **改同步机制 / 同步清单 / 自检脚本**：仍须全读完整规则回退包（现有硬规则不变）。
3. **`ai/commands/sync-methodology.md`**：必读文件链按同一口径补标注。

## 3. 影响与边界

- 只影响**读取成本**，不影响同步内容与行为；既有「标注外内容仍读全文、判断不了回退全读」的兜底语义原样沿用，正确性无回归风险。
- 普通派生路线与领域派生路线同适用（实证来自领域模板仓）。
- 不新增自检断言、不改 `template-sync.json`。

## 3.1 验证方式

- 落地后母仓 `check-template.*` 全量自检零变化（纯标注 + 条款区分，不新增断言）。
- 下一轮实盘同步按新标注执行，以 token hotspot 复测对比读取成本（预期 `document-lifecycle-rules` 不再全读）。
- 边界回归：同步中遇到标注外需求 → 回退全读仍合规，无正确性影响。

## 4. 与既有规则关系（去重）

| 既有规则 | 关系类型 | 说明 |
|---|---|---|
| `ai/index.md` 路由表脚注（v1.73.0 章节级标注语义） | 机制相同、对象不同 | 本提案是同一标注机制向同步类任务行的覆盖面扩展，互补不重复 |
| `ai/rules-core.md` §3「同步清单变更必须读完整回退包」 | 层级不同（收窄边界非冲突） | 改机制 / 改清单时仍全读；只有执行同步轮走标注 |
| `ai/commands/sync-methodology.md` 必读文件链 | 落点位之一 | 命令文件按同一口径标注，非替代 |
| `git-guide.md` §5 同步 SOP | 互补 | 该节已有窗口读取技巧（先 grep 标题再按行号读），本提案给规则层授权，两者叠加 |
