## 1. 动机（去项目化）

模板的任务体系已覆盖「计划侧」：任务卡五节格式（`ai/global-rules.md` §3）与 Task 文件五要素（`ai/implementation-lifecycle-rules.md` §4 第 4 条）保证开工前知道「做什么、改哪里、怎么验收」；Sprint 完成包（§7.1）保证收口后回写计划与验证文档。但**执行过程中**的关键上下文在模板里没有入库位：

1. **「为什么这么做」不可考**：范围裁决（用户决策、边界收缩）、开工前对现状代码的核实结论，散落在会话上下文里，随会话消失；正式文档只留「做了什么」的收口结论。
2. **执行记录无结构**：§4 第 4 条只要求「完成记录」存在——无叙事要素（遇到的问题 / 偏差与决定 / 验证计数），可审计性靠作者自觉，不同卡之间质量不可比。
3. **跨会话 / 跨机 / 跨 AI CLI 接手缺载体**：执行中状态默认在本地续接文件（gitignored、不入库）；多 AI 协作或换机执行时，接手方只能靠会话外渠道交接或重新考古。

**缺口（本提案补）**：把任务卡执行记录从「作者自觉」升级为「有结构、有入库定位、有接续自检」的默认形态。

## 1.1 与既有规则的关系（去重）

- **`ai/global-rules.md` §3（任务卡五节格式）**：**计划侧不动，增强执行侧**——五节原样保留，本提案只规范「执行过程怎么记」。
- **`ai/implementation-lifecycle-rules.md` §4 第 3 条（拆卡触发条件）**：**被引用，不改动**——「非平凡任务」判定沿用既有触发条件，不新增拆卡门槛。（2026-09-09 triage 校正：原提案引用「§4.3」；§4 实为编号列表、无子节，拆卡触发条件是第 3 条。）
- **`ai/implementation-lifecycle-rules.md` §4 第 4 条（Task 文件五要素）**：**直接增强对象**——五要素保留；「完成记录」一项由点要求扩展为结构化叙事（本提案 §2 第 3 项），其余要素不动。
- **`ai/implementation-lifecycle-rules.md` §5.1（设计可驱动性六问）**：**互补，提供卡级留痕位**——六问答「设计够不够开工」，事实基线记「代码现状是什么」；两者并存不冲突。
- **`ai/document-lifecycle-rules.md` §2.1（阶段最小产物与出口对照）**：**层级不同**——§2.1 管每阶段产物，本提案管单任务卡执行记录。
- **`ai/implementation-lifecycle-rules.md` §7.1（Sprint 完成包与正式回写）**：**分工不同，供证据**——任务卡执行记录粒度更细，是回写内容的证据源，不替代。
- **`ai/session-rules.md`（本地续接文件不入库）**：**边界互补，不合并**——续接文件管会话间临时续接（gitignored），任务卡执行记录管入库可审计记录。
- **`.ai/pitfalls/` 等本地观察日志**：**粒度不同**——观察日志是跨任务本地过程材料，任务卡执行记录是随任务本身入库的一等记录。
- **#407 / #408（六问 / 产物对照，均已落地）**：**同源不同面**——本提案是同一「外部实例 ↔ 模板方法论对照」评估的 R3「任务卡形态」半边；R1 / R2 已落地，无重叠。

**本提案不含**：交接开工检查三层（交付证据机械核对 / 语义核对 / 直接依赖核对）——来源项目零实证，按「实践复用一次才升规范」继续暂缓观察，留待后续独立评估。

**本提案不重复它们**：补的是「执行过程记录无结构、无入库定位、无接续自检」这块空白。

### 2.2 任务卡执行记录形态（四项内容标准 + 一项自检）

适用：§4 第 3 条触发条件拆出的非平凡任务卡；记录与代码同一 PR 入库。轻量任务（单点修复、纯文档收口等）可裁剪，留一行说明裁剪项；形态随任务重量自适应。

1. **范围决策记录**：裁决点（用户决策、边界收缩、方案取舍）在卡内留痕——决策点、结论、适用范围；作为「AI 不可自主扩展需求」的执行侧证据。
2. **开工前技术事实基线**：编码前对将触碰模块的核实结论（现状行为、关键约束、已知坑），一行一事实、注明核实日期；与六问分工——六问核设计完备性，事实基线记代码现状。
3. **完成记录叙事结构**（把 §4 第 4 条「完成记录」具体化，五要素）：实现记录（做了什么 + 提交 / PR 锚点）；遇到的问题（坑与当场修复方式）；偏差与决定（实现偏差 vs 设计缺口二分处置，衔接 §5.1 既有口径）；验证结果（命令 + 通过计数 + 失败项）；残留（未决项与下一步）。
4. **自包含执行节（可选，多机 / 跨环境协作形态）**：需移交执行的步骤写成自包含节——步骤、命令 / 脚本、证据回填位齐备，执行侧直接在卡内回填记录。
5. **可接续自检**：收卡自检「换个一无所知的 AI，只读这张卡和仓库，能接续吗」——不能则补卡后再收。

### 2.3 力度

**建议 + 默认**：非平凡任务卡默认采用本形态；项目可在 `ai/project-rules.md` 细化或声明豁免；不设机器门禁；存量任务卡不回溯改写。
