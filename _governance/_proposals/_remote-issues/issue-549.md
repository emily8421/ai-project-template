## 1. 动机

模板全部审核入口（`ai/prompts/review/19-docs-evaluation.md` / `10-docs-checklist.md` / `01-review-inputs.md` / `16-docs-system-audit.md` / `24-docs-health-review.md`）的检查维度均为「**链上追溯 + 结构完整 + 状态准确**」导向：

- 追溯性检查「已有 ID 的链路是否断裂」（U→REQ→Phase→AC/TC 向下追）；
- 完整性检查「必需文档 / 章节 / 矩阵 / 图表是否存在」（结构层）；
- 状态准确性检查「候选 / 降级 / 禁止等状态词使用是否正确」。

这套机制抓得住「**已有需求断了链**」，抓不住「**该出生而从未出生的需求**」——即核心领域实体的生命周期操作（创建 / 查询 / 修改 / 归档删除）从未进入需求层，且没有任何审核维度会提出「这个实体的创建操作在哪」这个问题。

**真实案例（去项目化）**：某知识库派生项目中，「空间」为第一级领域实体——第一条用户需求（隔离）即以其存在为前提，另有切换、加入等需求围绕它展开；但全部 57 条用户需求中无任何一条涉及空间的创建 / 改名 / 删除，且空间创建从未被「显式不做」裁决过（对比：同项目「邀请码 / 邀请链接」曾被显式砍除并留痕于 PRD 硬约束）。项目历经多轮阶段评估、系统审计、健康度复核均零检出；八个月后由终端用户在真实自托管使用中作为「缺陷」提出。此时「无创建入口」既无法从需求层证伪（没有需求说它该存在），也无法从边界决策证实（没有决策说不做）——文档链对该缺口完全失明。

## 3. 机制设计（去项目化）

**触发**：需求阶段生成（00-03）、E1 / E2 阶段评估、编码前清单核对。

**动作**：识别系统第一级领域实体（来源：00 场景名词 / 02 REQ 主语 / 06 概念模型，取并集，一般 ≤8 个），逐实体回答四问：

| 问 | 问题 | 空档含义 |
|---|---|---|
| C | 实体从哪来？（创建 / 导入 / 预置 / 注册派生） | 谁能在运行时造出它？没有答案 = 预置假设，需留痕 |
| R | 怎么被看见？（列表 / 查询 / 详情 / 切换） | 通常最先被满足（「能用」先行），缺 R 少见 |
| U | 怎么被修改？（编辑 / 改名 / 配置 / 成员管理） | 结构性实体的 U 常被误认为「当然有」 |
| D | 到哪去？（删除 / 归档 / 转移 / 停用） | 数据生命周期重决策，最常被显式延后——但须留痕而非沉默 |


**每个空档必须三选一留痕**：

1. **有需求**——挂 REQ-ID（进入正常追溯链）；
2. **显式不做**——登记进权威禁止清单（PRD 硬约束 / project-rules 禁止区）+ 理由 + 复审触发条件；
3. **不适用**——说明该实体为何无此操作（如纯派生实体：日志行不可改删）。

**力度**：提示性维度（非机器门禁）。AI 无法判定「应该可创建」——领域合理性是人的判断；本机制的价值是**逼人工表态**，把盲区里的事故变成表上的决策。与模板「反过度治理」哲学一致（无自检断言、无 CI 门）。

## 4. 与既有规则的关系（去重）

- **与追溯链规则（lifecycle §6）互补**：追溯管「已有 ID 链路不断」（存量校验），本机制管「ID 集合生成完备」（增量发现）；方向相反（自上而下追 vs 自实体正向问）。
- **与状态词典（§7.1）互补**：「禁止」状态有词典标准，本机制给「禁止」提供系统性的发现入口（没有发现机制，禁止清单只覆盖恰好被讨论过的边界）。
- **与阶段归属审计（19）正交**：那个管「内容放错层」，这个管「内容缺失」。
- **与 OO overlay（§2.1 事物-事件表 / 领域模型）不重复**：OO 产物是可选增强且少数项目选用；本机制用最小问答形态，不依赖 OO 产物，适用全部剖面（Lean 亦可裁剪为只答 C / D 两问）。

## 6. 验证计划与结果（派生项目试验）

- **试验结果（2026-11-13，task-107）**：**三问全过**——①检出有效性：Space 检出 C/U/D 三个空档（超出评估对话预期：当时仅发现 C，四问把同样从未被讨论的 U/D 一并逼出）；②泛化有效性：8 实体 32 问，1 真实缺口 + 1 候选确认（QuickEntry 草稿箱）+ 2 正当留痕确认（User 的 C/D），零误报，成本约 15 分钟；③留痕处置闭环：全部空档三选一落点（C → U-58/REQ-057/F-019 已入需求层；U/D → PRD 边界注记显式不做）。附带发现第三实例：REQ-055/056 在 03 已实现登记而 02 缺位（生成侧缺口家族）。
